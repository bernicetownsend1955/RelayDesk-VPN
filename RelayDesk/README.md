# RelayDesk

При обычном запуске без повышения прав приложение вызывает стандартный запрос Windows UAC и открывается от администратора после подтверждения. Отказ отменяет запуск. Отдельный запуск через контекстное меню не нужен.

Ядра привязаны к Windows Job Object: при аварийном завершении RelayDesk ОС завершает его дочерние ядра и освобождает их порты. При запуске проверяются остатки прежних версий. Завершение допускается только для сироты sing-box с конфигурацией RelayDesk, известным EXE и совпадающим временем запуска; связанный winws проверяется по тому же отсутствующему родителю. Процессы NekoBox и чужие конфигурации не останавливаются. Если порт занят другим процессом, сообщение содержит его PID и имя.

«Автоматика» разделена на маршруты, серверы, стратегии и голос. Ручные аргументы раскрываются отдельно; кнопки сохранения остаются внизу страницы. На страницах настроек журнал свёрнут, его можно раскрыть флажком «Журнал». На главной панели журнал виден сразу.

Вкладка «Соединения» показывает текущие TCP/UDP-соединения sing-box: процесс, назначение, выбранную цепочку выходов, правило и байты. Данные читаются раз в секунду через локальный Clash API. Введи `vesktop` или `discord` в поле фильтра. Пауза останавливает обновление списка, а не сеть. Закрытые соединения исчезают; история соединений не накапливается и на ВДС не отправляется.

«Напрямую» и «Через VPN / прокси» определяются по фактической цепочке выходов ядра, а не по имени приложения. Неизвестные цепочки остаются неопределёнными. Соединения вне этого sing-box не видны. При чтении API без собственного запущенного ядра источник помечается как внешний и состояние zapret неизвестно.

Столбец zapret сверяет назначение с аргументами запущенного winws. Совпадение с TCP-фильтром не подтверждает обработку пакетов или пользу обхода; для UDP и сложных ручных фильтров подтверждение не заявляется. Это ограничение наблюдения, а не показатель ошибки.

Если в профиле нет Clash API, RelayDesk добавляет его только в рабочую копию конфигурации: loopback-адрес и случайный секрет. DNS, правила и исходный профиль сохраняются. Существующий API не меняется. Используется [Clash API sing-box](https://sing-box.sagernet.org/configuration/experimental/clash-api/).

Приложение для Windows x64 на C# / WPF: две отдельные кнопки «zapret» и «VPN», выбранный сервер и журнал. Каждая кнопка включает и выключает свой процесс. Доступны системная, светлая и тёмная темы; выбор сохраняется.

## Запуск

Открой `dist/RelayDesk.exe`. Папку `dist` переносить целиком. Ядра не включены: выбери EXE из распакованного дистрибутива нужного проекта вместе с его зависимостями.

1. На вкладке «Ядра» укажи пути к EXE и сохрани. Для профилей из ссылок нужен sing-box 1.12 или новее; сформированные конфигурации проверены с 1.14.3.
2. Нажми «Вставить из буфера» или «Импортировать файл». Программа распознает формат и покажет предпросмотр до добавления профиля.
3. На вкладке «Настройки» выбери TUN, DNS и локальный порт для профиля из ссылки. Полный JSON/YAML остаётся ручной конфигурацией: его TUN и DNS редактируются в тексте.
4. Сохрани изменения. На вкладке «Конфигурация» нажми «Проверить ядром».
5. На панели нажми «VPN» для запуска VPN или «zapret» для запуска zapret. Повторное нажатие выключает соответствующий процесс. Кнопки «Настроить VPN» и «Настроить zapret» открывают их параметры.

Совместный запуск включается отдельно на вкладке «Автоматика» флажком «Запускать zapret вместе с VPN». Отключение VPN оставляет zapret включённым. «Остановить всё» выключает оба процесса. Режим маршрутизации Discord сам по себе не включает совместный запуск.

## Импорт

- VLESS, включая TLS / Reality, Vision, TCP, WebSocket, gRPC и HTTPUpgrade.
- VMess AEAD: Base64 JSON и URI. Старый alterId не поддерживается.
- Trojan с TLS.
- Shadowsocks: SIP002 и старый Base64-формат, без плагинов.
- JSON sing-box и Xray: ядро определяется по структуре. Если формат неоднозначен, его нужно выбрать в предпросмотре.
- JSON/YAML mihomo: YAML определяется по характерным полям; его синтаксис и параметры проверяет ядро.

Вставляется один сервер за раз. Неизвестные параметры и неподдержанные транспорты дают ошибку с пояснением. Подписки, QR и XHTTP через импорт ссылок пока отсутствуют; для XHTTP можно использовать полную конфигурацию соответствующего ядра.

Профиль из ссылки использует sing-box. При сохранении отредактированного полного JSON он становится ручным профилем. Настройки в полях больше не переписывают его конфигурацию.

## Автоматика и Discord

Флажок «Менять правила по состоянию VPN и zapret» включён по умолчанию. Он задаёт три режима:

| Включено | Применяемые правила |
| --- | --- |
| Только zapret | Без hostlist/ipset Discord, все TCP/UDP-порты. Реальная обработка зависит от DPI-стратегии; для UDP включено распознавание QUIC/Discord/STUN. VPN-соединения нет. |
| VPN и zapret | Discord, Vesktop и выбранные EXE обходят VPN; zapret ограничен Discord и указанными голосовыми IP. Остальные правила профиля сохранены. |
| Только VPN | Исходный профиль без добавленных исключений Discord/EXE. |

Кнопки переключают режим автоматически: запущенные процессы перезапускаются с новым набором правил. Это может прервать текущие соединения. Исходный JSON не перезаписывается. До остановки процессов проверяются пути и формирование новой конфигурации; при ошибке запуска программа пытается восстановить предыдущий режим. При аварийном выходе одного ядра правила оставшегося пересобираются.

Для повседневного профиля используй исходный второй JSON, а не ранее подготовленный `daily-discord.json`: в последнем исключения уже записаны в сам текст. Копия исходного файла находится в `user-config/daily-original.json`. Его DNS и все исходные маршруты сохраняются. Отключение условного режима возвращает ручные настройки разделения и области zapret.

На вкладке «Автоматика» включи выбор сервера при подключении. Проверяются отмеченные профили sing-box из ссылок и JSON с одним удалённым сервером и его тегом. Для каждого поднимается отдельный локальный вход без TUN и системного прокси. В тестовой копии JSON маршрут направляется к этому серверу, DNS и резолвер сохраняются; исходный профиль не меняется. Выполняются три HTTPS-запроса. Нужны два ответа 2xx; побеждает сервер с наименьшей медианой времени. После подключения он сам не меняется. Ошибка всех серверов останавливает подключение.

Режим «Discord — напрямую с zapret, остальное — через VPN» включает TUN у профиля из ссылки и добавляет direct-правила для Discord, Vesktop, его доменов и заданных IP голоса. Для полного JSON sing-box используются существующий TUN с auto_route=true и существующий direct-выход; DNS, серверы и исходные правила сохраняются. Исключения добавляются перед proxy-правилами. Для TUN нужны права администратора.

На вкладке «Автоматика» можно выбрать EXE-файлы. Их полный путь записывается в process_path-правило sing-box, чтобы они обходили VPN. Это не строгая фильтрация zapret по EXE: winws по-прежнему использует домены/IP. Изоляция обработки DPI по процессам требует отдельного механизма и пока не реализована. Обновление приложения в другую папку может изменить путь EXE; тогда выбери файл заново.

В режиме ограничения zapret стратегию составляют только DPI-аргументы. Программа добавляет TCP-фильтр 443 и hostlist Discord. Если заданы IP голосовых серверов, добавляется отдельный UDP-фильтр 50000–65535 с ipset и распознаванием Discord/STUN. Без IP нет широкого UDP-фильтра. WinDivert фильтрует трафик, поэтому такой режим не означает исключительной привязки к одному EXE; другой клиент тех же доменов также может попасть под фильтр.

«Проверить Discord» сравнивает доступность без zapret и с каждой стратегией. Проверяются HTTPS API и WebSocket Hello Gateway без входа в аккаунт. При доступности без zapret стратегия не меняется. Иначе сохраняется прошедшая проверки стратегия с наименьшим временем. Для проверки VPN можно оставить включённым: тестовые IPv4-сокеты привязываются к единственному активному Ethernet/Wi-Fi с шлюзом через Windows IP_UNICAST_IF. Системные маршруты не меняются; DNS использует системные ответы. Если интерфейс нельзя выбрать однозначно или DNS возвращает только fake-IP, проверка завершается ошибкой. Чужие winws-процессы не останавливаются: перед сравнением нужно остановить только zapret.

Кнопка «Загрузить TCP-стратегии Flowseal» читает `general*.bat` как текст. Переносятся DPI-параметры общей TCP-ветки и пути к fake-файлам внутри `bin`, одинаковые варианты объединяются. BAT-команды, установка службы, фильтры YouTube и GameFilter не исполняются. Это адаптация TCP-стратегий для ограничения Discord, а не запуск полного BAT. Выбранный вариант можно сохранить отдельной кнопкой, когда zapret остановлен; VPN отключать не требуется. Например, успешный результат `general (ALT11).bat` в тесте Flowseal — кандидат для проверки адаптированного ALT11, а не доказательство работоспособности всех режимов RelayDesk.

Полная проверка голоса без голосовой сессии не выполняется. При заданных IP:порт и SSRC текущей сессии проверяется UDP IP discovery и совпадение SSRC в ответе. Это подтверждает только обмен UDP-пакетами; аудио не отправляется. Без параметров результат голоса — «не проверен», даже если API и Gateway отвечают.

## Перенос из NekoBox / NekoRay и v2rayN

Вкладка «Импорт приложений» ищет известные папки и папки запущенных приложений. Для portable-версии укажи дополнительную папку или выбери файл. Перед переносом показываются профили и ошибки отдельных записей. Импортируются только отмеченные профили.

Поддержаны JSON профилей NekoRay 4, старый guiNConfig.json v2rayN, read-only чтение таблицы ProfileItem из guiNDB.db и TXT-экспорты ссылок. Для неподдерживаемого транспорта, сертификата или расширенных параметров нужен экспорт полной конфигурации. LMDB/LevelDB новых NekoBox напрямую не читаются: экспортируй ссылки в TXT и выбери этот файл.

По флажку одобренные записи обновляются при запуске и перед подключением. Их ID, локальный порт, DNS, TUN и участие в автовыборе сохраняются. Исходные файлы не изменяются; исчезнувшие записи не удаляются. Новые записи источника требуют отдельного предпросмотра. Глобальные настройки DNS/TUN и маршрутизация другого приложения не переносятся автоматически.

## Ручные проверки соединения

«Проверить TCP» измеряет установку соединения с сервером, включая разрешение его имени. Это не ICMP ping и не проверка работы протокола. Если в JSON несколько серверов, укажи один адрес и порт на вкладке «Настройки».

«Проверить HTTPS» отправляет запрос по заданному URL через локальный HTTP/SOCKS5-вход запущенного выбранного профиля. Прямого подключения при ошибке прокси нет. Проверка TLS-сертификата включена; автоматические перенаправления отключены. Показываются время до заголовков ответа и HTTP-код. Например, 403 — ответ сервера, а не успешная загрузка страницы. Маршрут внутри ядра определяется его конфигурацией: ручной JSON может отправлять этот URL напрямую.

Для ручного JSON/YAML проверь адрес локального входа на вкладке «Настройки»: он должен совпадать с конфигурацией. Вход с авторизацией потребует ручной настройки вне текущей формы.

Для zapret каждый аргумент задаётся отдельной строкой, например `--wf-tcp=443`. Не вставляй BAT-файлы, команды shell, символы продолжения строк и внешние кавычки. Рабочая папка процесса — папка EXE; относительные пути к спискам разрешаются оттуда. Для WinDivert нужны права администратора: при необходимости запусти RelayDesk от администратора.

Можно запустить один winws и одно прокси-ядро одновременно. Это не означает, что их правила совместимы: маршруты и фильтры задаются пользователем. Статус показывает процессы, а не доступность сайтов.

Профиль по умолчанию открывает локальный mixed-прокси на `127.0.0.1:2080` с прямым выходом. Он не содержит удалённого сервера и сам по себе не обходит блокировки.

Системный HTTP-прокси включается по флажку после запуска локального входа. Программа сохраняет прежние настройки Windows и восстанавливает их при отключении или закрытии. После аварийного завершения восстановление выполняется при следующем запуске. Если другая программа успела изменить настройки, они сохраняются. TUN и WinDivert требуют запуска RelayDesk от администратора. DNS в форме — IP-адрес UDP-резолвера ядра; системные DNS-настройки он не меняет.

## Обновления компонентов

Для VPN RelayDesk использует sing-box, для обхода DPI — zapret/winws. NekoBox остаётся отдельным приложением и для запуска RelayDesk не требуется.

Версии проверяются при запуске и раз в 6 часов. Новые пакеты загружаются автоматически, проверяются по SHA-256 и готовятся отдельно от работающих файлов. Текущее подключение продолжает работать. Флажок на вкладке «Обновления» отключает автоматическую проверку и очищает очередь установки.

Источники закреплены в приложении: RelayDesk — bernicetownsend1955/RelayDesk-VPN, sing-box — SagerNet/sing-box, zapret — Flowseal/zapret-discord-youtube, Xray — XTLS/Xray-core, mihomo — MetaCubeX/mihomo. Поле репозитория доступно только для чтения. Для внешнего ядра с неизвестной версией автоматическая замена может быть недоступна.

Ядра переключаются при следующем запуске. Перед этим проверяются файлы и сохранённые конфигурации; при ошибке остаётся прежняя версия. Обновление RelayDesk устанавливается после штатного закрытия или при следующем запуске, затем приложение открывается снова. Подтверждение внутри приложения не требуется; Windows может запросить права администратора.

Старые файлы не перезаписываются. Успешная установка меняет только выбранный путь компонента; запуск выполняется отдельной кнопкой. Кнопка возврата прежнего компонента также требует подтверждения. Настройки и профили пользователя не заменяются пакетами обновления. При отмене или ошибке прежний компонент остаётся выбранным; незавершённые загрузки могут остаться в папке components.

## Хранение профилей

Профили и рабочие конфигурации находятся в `%LOCALAPPDATA%/RelayDesk`. Пароли в конфигурациях хранятся открытым текстом. Экспорт записывает только текст конфигурации. При смене профиля или закрытии с несохранёнными изменениями появляется вопрос. При закрытии окна запущенные процессы останавливаются принудительно. Второй экземпляр приложения не запускается.

## Границы первой версии

Пока нет загрузки подписок по URL, форм всех параметров протоколов, общего редактора правил по приложениям, Kill Switch, трея, службы Windows и автозапуска. Точная настройка доступна через исходный JSON/YAML и аргументы winws. Доступ к удалённому VPN-серверу, фактический TUN, WinDivert и изменение системного прокси в этой среде не проверялись. Проверены синтаксис и приём правил Discord настоящим sing-box, выбор по результатам проверок, импорт на тестовых файлах JSON/SQLite и получение метаданных обновлений без установки.

## Сборка

Нужен .NET SDK 9 для Windows.

```powershell
dotnet build -c Release
dotnet publish -c Release -r win-x64 --self-contained true -o dist
```

Проверки парсера, конфигураций, локальной TCP-диагностики и отказа HTTPS при недоступном прокси:

```powershell
dotnet run --project ../RelayDesk.Checks -c Release
```

Для проверки с настоящим ядром передай папку для тестовых конфигураций и путь к sing-box.exe. UI-проверка: `../RelayDesk.Checks/UiSmoke.ps1`. Она использует отдельную папку данных. Переменная `RELAYDESK_DATA_DIR` задаёт папку данных для изолированного запуска.

- [Xray](https://github.com/XTLS/Xray-core)
- [mihomo](https://wiki.metacubex.one/en/)
- [zapret для Windows](https://github.com/bol-van/zapret/blob/master/docs/windows.md)
